# Схема проекта

## Файл

Агент пишет схему в `.bybai/map.json` в папке проекта. Окно перечитывает файл раз в три секунды, пока выбрана сессия из этой папки. Правила для агента лежат в `src/map/prompt.md`. Окно ставит их агенту навыком `bybmap`; человек вызывает его командой `/bybmap` в Claude Code или `$bybmap` в Codex.

```json
{
  "title": "Бот регистрации чеков",
  "groups": [{ "id": "bot", "label": "Бот" }],
  "nodes": [
    { "id": "rules", "kind": "service", "label": "Проверка условий", "tech": "Python",
      "note": "Проверяет дату и наличие акционного товара.", "group": "bot",
      "files": ["bot/rules.py"], "run": ["pytest tests/test_rules.py"] }
  ],
  "edges": [{ "from": "rules", "to": "registry", "label": "допущен" }]
}
```

| Поле | Правило |
|---|---|
| `nodes[].id` | латинские буквы, цифры и дефис; без повторов |
| `nodes[].kind` | `client`, `service`, `data`, `queue`, `external`, `security`, `infra`, `files` — задаёт значок и его цвет |
| `nodes[].label` | до 22 символов; `tech` до 22; `note` до 140 |
| `nodes[].files` | шаблоны путей от корня проекта: `**` — любая глубина, `*` — часть имени, каталог совпадает со всем внутри |
| `nodes[].run` | фрагменты команд, которые относятся к узлу |
| `nodes[].group` | id из `groups`; необязательно |
| `edges[]` | `from` и `to` — существующие узлы, не один и тот же; `label` до 16 символов; повтор связи пропускается |
| всего узлов | не больше 40 |

Проверка — `parseMap` в `src/map/spec.ts`. Ошибки написаны так, чтобы их можно было отдать агенту: окно показывает их и предлагает скопировать запрос на исправление.

## Раскладка

`src/map/layout.ts`, без сторонних библиотек.

1. **Ранг** узла — самый длинный путь до него по связям. Связи, замыкающие цикл, в расчёте не участвуют. Узел без входящих связей встаёт вплотную к тому, кого он питает.
2. **Группы** — полосы поперёк главной оси, в порядке объявления. Узлы без группы идут первой полосой без рамки.
3. **Порядок** узлов в ячейке (группа, ранг) подбирается по среднему положению соседей, три прохода.
4. **Направление** выбирается само. Строятся обе раскладки, слева направо и сверху вниз, и берётся та, что крупнее в окне 1240 × 640. Длинные цепочки обычно встают сверху вниз: узел широкий и низкий.
5. **Связи** — плавные кривые от стороны узла к стороне. Концы расходятся вдоль стороны, чтобы не сливаться. Связь через ранг в том же ряду идёт дугой сбоку, а не сквозь узлы между ними.

## Живая подсветка

`src/map/live.ts`. Действие агента относится к узлу так:

- чтение, правка, запись — по пути файла: побеждает самый длинный подошедший шаблон из `files`;
- команда — если её текст содержит фрагмент из `run`;
- остальные действия к узлам не относятся.

Состояние узла считается по действиям текущего хода:

| Состояние | Когда | Как видно |
|---|---|---|
| работает | действие идёт или закончилось меньше 2,5 секунды назад | лаймовое кольцо, пульсирует |
| ждёт человека | агент запросил разрешение на действие с этим узлом | оранжевое кольцо, метка «?» |
| ошибка | последнее действие на узле упало | красное кольцо, метка «✕» |
| правки | были завершённые правки или записи | метка «+N» |

Действия с файлами, которые не попали ни в один узел, считаются в нижней строке как «вне схемы». Если их много, схему пора обновить.

## Просмотр

- Щелчок по узлу — фокус: остаются яркими узел, его соседи и связи между ними, открывается карточка.
- «Откуда» и «Куда» в карточке — вся цепочка до узла и после него, с числом узлов.
- Открытая карточка отодвигает холст. Пока человек сам не двигал схему, она вписывается в свободную область.

## Сколько это стоит

Схема — единственное, на что уходят токены агента. Нижняя строка показывает оценку по выбранному проекту: длина правил навыка плюс длина записанного файла, делённые на три. На пробном проекте из шести файлов вышло около 1,2 тысячи токенов. Чтение кода, которое агент делает, чтобы понять проект, в эту оценку не входит.
