# ΒybAi · устройство приложения

## Назначение

Пока агент работает в терминале, человек видит в отдельном окне схему проекта и то, с какой её частью агент занят прямо сейчас. Приложение пассивно: оно не управляет агентом и ничего не добавляет в его контекст. Токены агента тратятся один раз — когда человек просит его составить схему.

## Поток данных

```text
Claude Code ── HTTP-хук ───────────────┐
                                       ├─► 127.0.0.1:4517   слушатель в процессе окна (Rust)
Codex CLI ── командный хук (curl) ─────┘      │  ответ 204 без тела
                                              ▼
                                   событие «hook» в окно
                                              │
                    normalizeClaude / normalizeCodex → reduce        действия, план, файлы
                                              │
агент пишет .bybai/map.json ─► read_map ─► parseMap → layout         схема и её раскладка
                                              │
                                     live: действия × схема          какой узел сейчас в работе
                                              │
                          TopBar · PlanBar · Canvas · Card · StatusLine
```

Слушатель ничего не знает об агентах: принимает тело, сворачивает длинные строки и пересылает дальше. Разбор хуков, схема и подсветка живут в TypeScript и проверяются тестами без окна и без Rust.

## Решения

| Решение | Почему |
|---|---|
| Хуки, а не MCP | Описания MCP-инструментов попадают в каждый запрос модели. Хук с пустым ответом не стоит ничего |
| Схему заказывает человек, запросом из буфера | Навык или инструкция в настройках агента занимали бы контекст в каждой сессии. Запрос тратит токены только тогда, когда схема нужна |
| Схема — файл в папке проекта | Агент пишет его обычным инструментом записи; файл можно править руками и хранить в git |
| Свой формат и своя раскладка | Нужен один тип схемы и живая подсветка. Сторонний движок был бы тяжелее всего остального приложения |
| Узел знает шаблоны своих файлов | По ним действие агента сопоставляется с узлом без единого токена |
| HTTP-хук для Claude Code, `curl` для Codex | У Claude событие уходит прямо в окно; у Codex другого типа хуков нет, хук помечен `async` |
| Хуки ставятся при запуске и убираются при выходе | Когда окно закрыто, у агента нет ни лишних запросов, ни лишних процессов |
| Отдельное окно на Tauri | Один exe около 3 МБ, системный WebView2, слушатель в том же процессе |

## Экран

| Область | Что видно |
|---|---|
| Верхняя полоса | Вкладки сессий с точкой состояния, поиск узла, включение агентов, «поверх окон» |
| Строка плана | Сегменты шагов, счёт и текущий шаг; по щелчку — весь список. Скрыта, если плана нет |
| Холст | Схема: группы, узлы со значком роли, связи с подписями; масштаб и легенда ролей по углам |
| Карточка узла | Появляется по щелчку: описание, «Откуда» и «Куда», действия агента за ход, связи, файлы |
| Нижняя строка | Действие, которое идёт сейчас; число действий вне схемы; оценка стоимости схемы; счётчик хуков |

Окно по умолчанию 1280 × 800, минимум 720 × 480. По умолчанию показана сессия, где что-то происходило последним; выбор вкладки закрепляет сессию.

## Ограничения

- Один тип схемы: архитектура. Процессы, последовательности и остальное пока не поддерживаются.
- Схема не обновляется сама: когда проект изменился, человек снова даёт агенту запрос.
- Действия поиска и веб-запросы к узлам не относятся.
- Команды Codex не делятся на чтение и поиск: любая команда оболочки показана как команда.
- План Claude Code в режиме планирования приходит текстом и в строке плана не показывается.
- Состояние живёт в памяти окна. После перезапуска приложения прошлые сессии не восстанавливаются.
- Экспорта схемы в картинку нет.

## Приёмка

1. `npm test` — разбор хуков, схема, раскладка, подсветка.
2. `npm run build` — проверка типов и сборка интерфейса.
3. `cargo test` в `src-tauri` — свёртка строк и установка хуков на временных папках.
4. Контрольный кадр: открыть окно с `BYBAI_HOME` на временную папку и выполнить `npm run replay -- fixtures/receipt-bot.jsonl --until 31 --speed 60`. Экран совпадает с `design/reference.png`.
5. Живая проверка: дать агенту запрос на схему в маленьком проекте; файл проходит `parseMap` без ошибок.
