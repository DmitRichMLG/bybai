# ΒybAi · устройство приложения

## Назначение

Пока агент работает в терминале, человек видит в отдельном окне его план, текущий шаг и каждое действие в момент начала. Приложение пассивно: оно не управляет агентом и не добавляет ничего в его контекст.

## Поток данных

```text
Claude Code ── HTTP-хук ───────────────┐
                                       ├─► 127.0.0.1:4517   слушатель в процессе окна (Rust)
Codex CLI ── командный хук (curl) ─────┘      │  ответ 204 без тела
                                              │  сворачивание длинных строк, номер и время приёма
                                              ▼
                                        событие «hook» в окно
                                              │
                         normalizeClaude / normalizeCodex   общий язык событий
                                              │
                                           reduce           состояние сессий
                                              │
                                  TopBar · Mast · Lanes · PlanPanel · StatusLine
```

Слушатель ничего не знает об агентах: он принимает тело, сворачивает длинные строки и пересылает дальше. Вся логика разбора живёт в `src/model/` на TypeScript и проверяется тестами без окна и без Rust.

## Решения

| Решение | Почему |
|---|---|
| Хуки, а не MCP | Описания MCP-инструментов попадают в каждый запрос модели, вызовы тоже стоят токенов. Хук с пустым ответом не стоит ничего |
| HTTP-хук для Claude Code | Событие уходит прямо в окно, без запуска процессов на каждое действие |
| Командный хук с `curl` для Codex | Другого типа хуков у Codex нет. Хук помечен `async`, поэтому агент его не ждёт |
| Хуки ставятся при запуске и убираются при выходе | Когда окно закрыто, у агента нет ни лишних запросов, ни лишних процессов |
| Отдельное окно на Tauri | Один небольшой exe, системный WebView2, слушатель в том же процессе |
| Разбор событий в окне, а не в Rust | Проверяется тестами; тот же код работает в браузере с мостом `dev/bridge.mjs` |
| Длинные строки сворачиваются в слушателе | Ответы инструментов бывают в сотни килобайт; экрану нужны только счётчики и начало текста |

## Экран

| Область | Что видно |
|---|---|
| Верхняя полоса | Вкладка на каждую сессию с квадратом состояния, кнопки подключения агентов и «поверх окон», состояние выбранной сессии |
| Заголовок | Последний запрос человека, время начала, длительность и число действий текущего хода |
| Лента | Шаги сверху вниз; в шаге цепочка действий слева направо; причина последней ошибки раскрыта под цепочкой |
| Колонка плана | Счётчик и сегменты прогресса, шаги со статусами, изменённые файлы |
| Нижняя строка | Действие, которое идёт сейчас, и счётчик «ΒybAi → агенту» |

Окно по умолчанию 1280 × 800, минимум 720 × 480. При ширине меньше 860 px план встаёт над лентой. Лента следует за последним действием, пока человек не прокрутил её вверх. По умолчанию показана сессия, где что-то происходило последним; выбор вкладки закрепляет сессию.

```text

  ui/
```

## Ограничения первой версии

- План Claude Code в режиме планирования приходит текстом и показывается как текст, без шагов.
- Команды Codex не делятся на чтение и поиск: любая команда оболочки показана как команда.
- Хуки Codex асинхронны, поэтому время начала и конца действия — это время приёма события, а не время в агенте.
- Состояние живёт в памяти окна. После перезапуска приложения прошлые сессии не восстанавливаются.
- Сессия, начатая до подключения хуков, появится с первого следующего действия.

## Приёмка

1. `npm test` — разбор хуков обоих агентов и состояние на записи `fixtures/demo.jsonl`.
2. `npm run build` — проверка типов и сборка интерфейса.
3. Контрольный кадр: `npm run replay -- fixtures/demo.jsonl --until 48 --speed 50` даёт экран из `design/reference.png`.
4. `cargo test` в `src-tauri` — сворачивание строк и установка хуков на временных папках. Собранное окно проверяется с переменной `BYBAI_HOME`, которая подменяет домашний каталог.
5. Живая проверка: сессия Claude Code и сессия Codex с подключёнными хуками; план, действия и ожидание разрешения видны в окне, счётчик показывает 0.
