# События и состояние

Здесь описано, что присылают агенты и как из этого собирается состояние сессии. Как действия попадают на схему — в `docs/map.md`.

## Слушатель

`127.0.0.1:4517`, принимает только `POST /hook/claude` и `POST /hook/codex`.

- Отвечает `204` без тела до любой обработки. Агенту не возвращается ни байта.
- Запрос с заголовком `Origin` получает `403`: его шлют страницы в браузере, хуки агентов — никогда.
- Тело, которое не разобралось как JSON, пропускается.

Каждое принятое тело уходит в окно как конверт:

```json
{ "seq": 17, "at": 1795000000000, "source": "claude", "replied": 0, "body": { } }
```

`seq` растёт с 1, `at` — время приёма в миллисекундах, `replied` — сколько байт слушатель вернул агенту. Последние 5000 конвертов хранятся в памяти, чтобы окно получило их при старте.

### Сворачивание строк

Длинная строка заменяется объектом, в котором сохранены счётчики и начало текста:

```json
{ "$trim": true, "chars": 48211, "lines": 902, "head": "первые 300 символов" }
```

Порог зависит от места: внутри `tool_response` — 2048 символов, в остальном теле — 65536. В `tool_input` лежат патчи и содержимое файлов, по которым считаются строки, поэтому там порог выше. Правило одинаково в `src-tauri` и в `dev/bridge.mjs`.

## Хуки агентов

| Событие | Claude Code | Codex CLI | Что получается |
|---|---|---|---|
| `SessionStart` | да | да | сессия появилась |
| `UserPromptSubmit` | да | да | новый ход: заголовок задачи, счётчик хода |
| `PreToolUse` | да | да | действие началось |
| `PostToolUse` | да | да | действие завершилось |
| `PostToolUseFailure` | да | — | действие упало; у Codex код выхода ищется в ответе команды |
| `Notification` с `permission_prompt` | да | — | агент ждёт человека |
| `PermissionRequest` | — | да | агент ждёт человека |
| `Stop` | да | да | ход завершён |
| `SessionEnd` | да | — | сессия закрыта |

У Claude Code хук имеет вид `{"type":"http","url":"http://127.0.0.1:4517/hook/claude","timeout":1}`. У Codex это команда с `curl`, помеченная `async`; её текст не должен меняться между установками, иначе Codex потребует подтвердить хук заново.

### Что считается действием

| Вид | Claude Code | Codex CLI |
|---|---|---|
| чтение | `Read` | `view_image` |
| правка | `Edit`, `NotebookEdit` | `apply_patch` |
| запись | `Write` | `apply_patch`, если все файлы новые |
| команда | `Bash`, `PowerShell` | `Bash` |
| поиск | `Grep`, `Glob` | — |
| веб | `WebFetch`, `WebSearch` | — |
| субагент | `Task`, `Agent` | `spawn_agent` |
| mcp | `mcp__сервер__инструмент` | то же |
| вопрос | `AskUserQuestion` | — |
| вызов | любой другой инструмент, под своим именем | то же |

### Откуда берётся план

| Источник | Что приходит |
|---|---|
| Claude Code `TodoWrite` | весь список с статусами |
| Claude Code `TaskCreate` / `TaskUpdate` | по одному шагу: создание и смена статуса |
| Claude Code `ExitPlanMode` | план текстом; показывается, пока нет списка шагов |
| Codex `update_plan` | весь список со статусами |

`TaskList`, `TaskGet`, `EnterPlanMode` и `ToolSearch` действиями не считаются.

## Общие события

Нормализаторы превращают тело хука в ноль или несколько событий. У каждого есть `sid`, `source`, `at` и, если известно, `cwd`.

| `t` | Поля | Смысл |
|---|---|---|
| `session` | — | сессия началась или возобновилась |
| `prompt` | `text` | запрос человека, первая строка |
| `start` | `id`, `kind`, `target`, `note?`, `files?` | действие началось |
| `end` | `id`, `ok`, `note?`, `error?`, `created?` | действие завершилось |
| `plan` | `id`, `steps[]` | план целиком |
| `step` | `id`, `text?`, `status?` | один шаг создан, изменён или удалён |
| `plan-text` | `text` | план свободным текстом |
| `waiting` | `text` | агент ждёт человека |
| `stop` | — | ход завершён |
| `close` | — | сессия закрыта |

## Правила состояния

- **Шаг действия.** Действие относится к шагу, который был в работе в момент его начала. По этому в списке плана считается, сколько действий пришлось на шаг.
- **Опознание шага.** В плане, который приходит целиком, шаг опознаётся по тексту, поэтому цепочки действий переживают пересылку плана. Шаги из `TaskCreate` опознаются по идентификатору задачи.
- **План как действие.** Изменение состава плана считается действием. Смена статусов действием не считается.
- **Текущий ход.** Подсветка схемы, счётчики и список плана считаются по действиям текущего хода: от последнего запроса человека.
- **Счёт строк.** У правки считаются только изменённые строки: общие строки в начале и в конце старого и нового текста пропускаются. У записи — все строки файла.
- **Ошибка.** У команды Claude Code первая строка «Exit code N» становится пометкой «код N», причина берётся из следующей строки. У Codex код выхода ищется в ответе команды.
- **Ожидание.** Событие `waiting` помечает последнее идущее действие и всю сессию. Любое следующее действие или завершение снимает ожидание.
- **Порядок.** Хуки Codex асинхронны, завершение может прийти раньше начала. Такое завершение хранится и применяется, когда приходит начало.
- **Без результата.** Вызов, который человек или режим разрешений отклонил, не присылает завершения. Если тот же поток (основной агент или один субагент) начинает новое действие, а предыдущее открыто дольше 1,5 секунды, оно закрывается с пометкой «отклонено» (если агент ждал разрешения) или «нет результата». Субагенты под это правило не попадают: они работают долго. Если завершение всё же приходит, пометка снимается.
- **Конец хода.** Действия, которые не успели завершиться к `stop` или `close`, помечаются «прервано».
- **Пределы.** На сессию хранится 2000 последних действий. Во вкладках держится до 8 сессий: когда появляется девятая, уходит самая давняя из закрытых, а если закрытых нет — из простаивающих. Сессия, в которой агент работает или ждёт, не убирается.

## Счётчики нижней строки

**Хуки → агенту.** Сумма поля `replied` по всем принятым конвертам, пересчитанная в токены как байты, делённые на четыре с округлением вверх. Слушатель отвечает пустым телом, поэтому при обычной работе это 0. Подсказка показывает число принятых событий и возвращённых байт.

**Схема.** Оценка токенов, которые ушли на схему: длина запроса человека, в котором упомянут `.bybai/map.json`, плюс длина того, что агент записал в этот файл, делённые на три. Появляется, когда агент составлял или правил схему в этой сессии.

В контекст модели попадает только то, что хук вернул: текст в ответе или поле `additionalContext`. ΒybAi не возвращает ничего, а командный хук Codex глушит вывод `curl` и всегда завершается кодом 0.
