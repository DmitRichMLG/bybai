# ΒybAi

Собери русскоязычный локальный визуализатор работы агента. Человек ставит задачу агенту в своей CLI-среде. Агент планирует работу, ведёт описание проекта и запускает проверки. ΒybAi читает опубликованный граф и результаты проверок.

## Исходные материалы

Перед реализацией посмотри `design/reference.png` и `design/states.png`, затем прочитай `docs/architecture.md`, `docs/events.md`. Для демо используй готовые записи в `fixtures/receipt-bot/`. Если потребуется сменить согласованную логику продукта или геометрию экрана, уточни у владельца. Обычные решения по реализации принимай самостоятельно.

## Решения по интерфейсу

- Используй название **ΒybAi**. Первый символ — греческая заглавная бета.
- Главный экран состоит из тёмной верхней полосы, светлого холста слева, постоянной колонки тестов справа и строки CLI снизу.
- Рабочий граф читается слева направо. Соединяй порты ортогональными стрелками. Показывай входы из конфигов, альтернативные исходы и причины выхода.
- На узле видны действие, используемая технология и результат. Человек должен понять, откуда пришли данные и почему выбран конкретный исход.
- Холст свободно перемещается и масштабируется. При открытии схема вписана в холст. Панель тестов и нижняя строка CLI остаются на месте.
- Группы тестов идут сверху вниз. Все подтесты, их статусы и причина ошибки доступны в самой группе. Ожидание обозначай разомкнутым кольцом; активную проверку — синим индикатором и подписью «Идёт»; упавшую — «✕ Упал» с причиной, раскрытой под строкой без клика. Колонка прокручивается отдельно от холста.
- Поддерживай спокойный контраст и плоские заливки. Цвет показывает только состояние прогона: синий — выполняется сейчас, красный — проверка упала. Роль связи показывает рисунок линии; терракота отмечает ветки-исключения, конфиги нейтральные. Цвет всегда продублирован знаком или словом.
- Цвета, шрифты и кегли бери из `design/tokens.css`, стили компонентов — из `design/components.css`, состояния — из `design/states.html`. Новых значений мимо токенов не вводи.
- Пиксельный шрифт используй в логотипе; он лежит в `design/fonts/`, сетевых запросов за шрифтами нет. Для имён файлов, технологий и событий используй моноширинный.
- Все действия с проектом выполняет внешняя CLI. В интерфейсе доступны только навигация и просмотр. Запуск pytest, редактор графа, ключи моделей и чат находятся вне объёма первого выпуска.

## Граница проекта

Telegram-бот — демонстрационный наблюдаемый проект. Python, aiogram, ZXing-C++, HTTPX и PostgreSQL на схеме описывают его реализацию. Данные об акциях принадлежат проекту бота. Файл `promo.yaml` определяет условия допуска чека. Для воспроизведения демо достаточно локальных файлов.

## Определение готовности

Пользователь открывает приложение и видит тот же проект, ветки и статусы, что на референсе. Событие из внешней CLI обновляет подтест, соответствующий узел, счётчик и строку активности. Обновление работает без ручной перезагрузки и сохраняет положение камеры.
