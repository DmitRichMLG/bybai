# ΒybAi · состояние на 27 ноября 2026

Файл для быстрого старта следующей сессии: что сделано, что проверено, что осталось.

## Что это сейчас

Окно на Tauri. Агент по команде человека записывает схему архитектуры проекта в `.bybai/map.json`; окно рисует её на тёмном холсте и подсвечивает узлы, с которыми агент работает прямо сейчас. Вкладка окна — проект. По каждому проекту окно считает расход токенов агента и хранит статистику. Пока окно свёрнуто, поверх экрана висит плашка-светофор по проектам. Подсветка идёт через хуки Claude Code и Codex и не стоит токенов. Образец по функционалу — открытый проект archify; движок, формат и значки свои.

- Репозиторий: эта папка, ветка `main`. На GitHub — публичный `DmitRichMLG/bybai` (открыт владельцем 27 ноября 2026). Коммиты подписаны скрытым адресом GitHub; так настроено только в этом репозитории.
- Готовый exe: `src-tauri\target\release\bybai.exe` (около 3,6 МБ). Папка `target` в git не входит; пересборка — `npm run tauri build -- --no-bundle`.
- Как выглядит: `design/reference.png` (обычный вид), `design/focus.png` (фокус на узле и трассировка), `design/readme/` (картинки для README), `design/mock/next.html` (макеты, принятые владельцем; кадры из них в git не входят).
- В репозиторий не попадает ничего про машину владельца: заметки о ней лежат в `STATUS.local.md`, картинки обезличены, пути в примерах вымышленные. Перед отправкой это проверено по файлам и по истории коммитов.

## Как попробовать

1. Запустить `src-tauri\target\release\bybai.exe`.
2. Демо без агента: в терминале в этой папке `npm run replay -- fixtures/receipt-bot.jsonl --speed 4`.
3. С настоящим агентом: включить `claude` в верхней полосе, начать сессию Claude Code в папке любого проекта и набрать в ней `/bybmap` (в Codex `$bybmap`).
4. Свернуть окно: в углу экрана появится плашка. Вид, угол и режим кликов меняются в настройках (кнопка справа вверху).

## Решения владельца

- Ядро: схема от агента плюс живая подсветка. Текстовая лента действий отвергнута: «слишком много текста и визуально неприятно».
- Свой движок с выбранным набором, а не код archify. Значки свои.
- В первой версии один тип схемы: архитектура.
- Тёмный холст.
- Отдельное окно на Tauri, а не вкладка браузера.
- Агенты: Claude Code и Codex CLI.
- Расход токенов агента должен быть минимальным и видимым в окне.
- Схема заказывается командой-навыком `bybmap` (`/bybmap`, `$bybmap`), а не вставкой правил из буфера. Навык ставится сам, вместе с хуками, и вызывает его только человек.
- Поиск узла убран.
- Вкладка — проект. Прошлые проекты сохраняются и открываются кнопкой «+»; там же открывается папка без сессии.
- Токены считаются по проекту, а не суммой. Считается реальный расход агента; расход самого ΒybAi показан отдельно.
- Меню настроек: готовые темы плюс свои цвета; по умолчанию вид прежний.
- Плашка при сворачивании — светофор: серый — работа не начата, мигающий лаймовый — агент работает, оранжевый — ошибка или подтверждение, зелёный — готово. Строка на проект: фонарь, имя, процент шагов, токены. Плюс расход подписки, если агент работает по подписке; по API — только токены. По умолчанию плашка пропускает клики, режим выбирается в настройках.
- Ради расхода подписки Claude Code окно ставит ему свою строку состояния, пока открыто. Владелец это разрешил.

## История

1. В папке лежали материалы от GPT и Codex про другой продукт: граф проекта с панелью pytest на светлой теме. Они разобраны и сохранены в первом коммите.
2. Первая версия (второй коммит): окно, слушатель хуков, разбор событий обоих агентов, экран в виде ленты шагов и действий. Владельцу экран не подошёл.
3. Вторая версия (третий коммит): экран заменён схемой. Слушатель, хуки и модель событий остались прежними.
4. Навык `bybmap`: правила схемы переехали в `src/map/prompt.md`, окно ставит их агентам навыком и снимает при выходе. Сначала навык назывался `bybai-map`. Владелец посмотрел окно на чужом проекте (boobvoice, схема из 15 узлов) и подтвердил, что схема строится правильно.
5. Проекты, статистика, настройки, плашка. Сначала владельцу показаны макеты (`design/mock/`), он их принял с одной правкой: плашка должна быть светофором и занимать мало места.
6. Первая отправка на GitHub: проверка приватности, новый README с картинками, пункты 4 и 5 закоммичены одним коммитом.
7. Владелец проверил Codex на проекте из Roblox Studio (через MCP, сессия из домашней папки). Схема появилась только после двух напоминаний: агент не понял, куда писать файл для проекта не с диска, а при отказе песочницы в записи сохранил его во временной папке. В правила навыка добавлено: составлять схему сразу, писать в рабочую папку сессии, при отказе не сохранять в другом месте.

## Что не проверено

- **Расход на настоящих журналах.** Формат журналов сверен с настоящими файлами на этой машине (у Claude Code — `message.usage`, у Codex — события `token_count`), но сквозная проверка шла на поддельных журналах того же формата.
- **Строка состояния в терминале Claude Code.** Что строка «5ч 42% · 7д 18%» действительно появляется внизу терминала, подхватывается ли она в уже открытой сессии и как выглядит кириллица, глазами не смотрели.
- **Codex вживую.** Разбор его хуков написан по исходникам Codex 0.172 и проверен на синтетических телах. Ни одной настоящей сессии Codex с хуками не было. Владелец проверит Codex сам.
- **Навык в Codex: интерактивный режим.** Вызов `$bybmap` из `~/.codex/skills/bybmap` и запрет неявного вызова работают в 0.172 (см. «Что проверено»; в сессии владельца навыка не было в списке, который видит модель). Не смотрели, показывает ли его подсказка при наборе `$` в окне Codex. В исходниках `~/.codex/skills` помечен как устаревшее место, новое — `~/.agents/skills`.
- **Новые правила навыка на проекте не с диска.** Случай владельца (Codex из домашней папки, проект в Roblox Studio) с новым текстом не повторяли. В Claude Code новый текст не запускался.
- **Claude Code в интерактивном режиме.** Запрос разрешения и переход узла в «ждёт человека» вживую не наблюдались; оранжевый фонарь плашки проверен только тестом.
- **В настоящем окне не нажимались:** «+» и «Открыть папку…» (диалог выбора папки), меню настроек и выбор своих цветов, карточка статистики, кликабельный режим плашки и её перетаскивание. Всё это, кроме диалога и плашки, нажималось в браузере.
- **Плашка при долгом сворачивании и на втором мониторе.** Проверено несколько секунд на одном экране.
- **Раскладка слева направо** проверена тестом, но не глазами: демосхема встаёт сверху вниз.
- **Установщик NSIS** не собирался.

## Известные слабые места

- Отклонённый вызов инструмента не присылает завершения. Узел перестаёт светиться, когда агент начинает следующее действие; до этого он выглядит работающим.
- Связь через несколько рангов в другую группу может пройти поверх чужого узла.
- Сессия числится за проектом, в папке которого она сейчас: если агент перешёл в другую папку, весь её расход уходит туда.
- Если агент при возобновлении копирует историю в новый журнал, расход посчитается дважды.
- В памяти держится не больше восьми сессий; счётчики более старых остаются в статистике, но их действия не видны.
- Схема не обновляется сама, а счётчик «вне схемы» только намекает, что она устарела.
- Песочница Codex в Windows не выдаёт права на запись в корень домашней папки, хотя числит её рабочей. Сессия, начатая из домашней папки, записать `.bybai/map.json` не может; из папки проекта запись проходит. Агент об отказе скажет, но обойти его не может.
- Проект, который агент правит не через файлы (Roblox Studio через MCP), получает схему без подсветки: действия MCP к узлам не относятся, а пути в `files` у такой схемы не совпадают ни с чем на диске.
- Все сессии из одной папки — один проект и одна схема. Два разных проекта, открытых из домашней папки, перезапишут схему друг друга.
- Плашка всегда встаёт в выбранный угол; место, куда её перетащили, не запоминается.
- Свой цвет «Холст» меняет только фон холста: полосы и карточки остаются от темы.
